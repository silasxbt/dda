# 覆盖率优先的下一轮研究

用户选择：先提高真实采样与成交数据覆盖。保持资产等价、时效与未知标签边界，不提高缺失数据的放行率。

## 现有瓶颈与优先级

1. **报价读取**：Solana 官方 SDK 单池完整报价读取多个账户、配置、tick、vault、epoch。四池交错会拉长状态跨度。已隔离 slot 跟踪、限制账户缓存至单池、串行单池快照。下一步用 SDK 官方批量池 / tick API 减少非必要请求，同时保留每项依赖 slot；不要用延长过期阈值伪装优化。
2. **成交读取**：全局约四秒预算、每池签名三条或日志十二条，很容易截断。应把成交摄取与报价独立调度，保存持久游标，按 RPC 能力分页追平，原始响应与 availableAt 保留。追平期间只回填历史成交，不能回填为决策当时已知。
3. **节点一致性**：部分 BSC 公共后端的日志高度落后读取 head，产生查询越界；应记录每个端点可读高度并固定会话来源。不要无标记地混用来源或吞掉缺口。
4. **Solana 新交易版本**：当前 SDK 只明确处理 legacy/v0。RPC 遇 version 1 返回不支持；需先验证官方编码、解析结果和账户索引语义，再升级支持并增加真实夹具，失败继续标未知。

## 验收方法

单一采集器、固定八池、相同规模和时效阈值，至少三十分钟对照；同一时间重复会话共享公共节点会干扰吞吐，不能据此估计优化增益。逐池比较有效指定金额报价 / 期望报价、真实间隔中位数与 P95、30 秒完整成交窗口、已知竞争特征比例、5/15 秒标签覆盖、429 / 超时和单位周期请求数。完整窗口与有效报价均需改善，才能增加研究样本；策略收益在此之前不作结论。

本轮短检查只定位问题，不能证明长期改善。原三十分钟样本保留作诊断基底；其读取算法与后续优化版本分开记录。
